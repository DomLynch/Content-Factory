What the vampire v2 run taught, in one page. **E** = enforced by a gate or tool, **R** = rule in the skills (the Factory follows it, nothing blocks it yet), **P** = pending (listed in `cf_chain.PENDING`).

Escape hatch for every **E** gate is the same as before: `FACTORY_RAW=<reason>` (logged); the MCP tools have none.

## Latest-models gate (plugin 0.1.27)

Dom's mandate: before ANY generation the tool about to run is compared with its upstream. `config/config.json -> models.registry` lists every tool (name, the stages it serves, how its installed version is found: git clone / model folder / pip package / pinned, and how its upstream latest is found: GitHub HEAD or release, Hugging Face revision, PyPI); no model name or number lives in code. `flux_kit.py`, `run_3d.py` (cut-out and TRELLIS), `run_pixal3d.py`, `upscale_match.py`, `run_bind.py` and `run_skin_tokens.py` call the gate after the other gates. A tool that is BEHIND upstream refuses the run unless it carries `--allow-stale "<reason>"` (or `FACTORY_ALLOW_STALE`), and both the installed and upstream versions, the check time and the reason are written to the receipt (`models_check`). The upstream lookup is cached 24 h in `state/models_upstream.json`; with no network the cached value is used and the row is marked `verified: false`, with nothing cached or an unknown installed version it is `unverified` and the run goes ahead. A git row is current when the upstream commit is the installed commit or one of its ancestors; if the upstream commit is not in the local clone it counts as behind (fetch the upstream into the clone first). The TRELLIS row reads the clone named by `trellis_checkout_dir` in `config.local.json` (the checkout the Factory really runs), else `trellis_repo_dir`; until that clone contains upstream, a Trellis run carries `--allow-stale "<reason>"` and the reason lands in the receipt. To cover a new tool add a registry row; to cover a new stage add the `plugin_gate("models", "<stage>")` call to its entry script.

## Quality first (plugin 0.1.27)

Dom's standing order: no speed, max quality. The default presets are the hero settings (`trellis.presets.hero`: 8192 texture, 2M-face bake, 98304-token floor, NOT yet proven on this GPU; `pixal3d` master). A preset listed in `config.json -> quality.speed_presets` (`master_reduced`, `attn24`, `tokens98k`, `tokens98k_fresh`, `plain`, Pixal3D `draft` and `standard`) runs only with `--speed-reason "<reason>"` (MCP: `speed_reason`) and the reason is written to the receipt as `quality`. Flux steps below the floor and a reference below the render edge were already refused. Cut-out resolution and the post-Flux 4x upscale are unchanged (the cut-out has no reduced mode; the upscale is a separate step).
